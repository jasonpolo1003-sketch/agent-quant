# Trade Fills

## Key Concepts[](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#01-Key-Concepts)

### Introduction [](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts/01%20Introduction.html)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#01-Introduction)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)

A trade fill is the quantity and price at which your brokerage executes your order in the market. Fill models model how each type of order fills to accurately simulate the behavior of a real brokerage. Fill models determine the price and quantity of your fills, can incorporate spread costs, and work with the [slippage model](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/slippage/key-concepts) to add slippage into the fill price. If you trade US Equities, our built-in fill models can fill your orders at the [official opening and closing auction prices](https://www.quantconnect.com/docs/v2/cloud-platform/datasets/misconceptions#07-Opening-and-Closing-Auctions).

### Set Models [](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts/02%20Set%20Models.php)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#02-Set-Models)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)

The brokerage model of your algorithm automatically sets the fill model for each security, but you can override it. To manually set the fill model of a security, call the `SetFillModel``set_fill_model` method on the Security object.

 Select Language: C#Python

You can also set the fill model in a [security initializer](https://www.quantconnect.com/docs/v2/writing-algorithms/initialization#07-Set-Security-Initializer). If your algorithm has a dynamic universe, use the security initializer technique. In order to initialize single security subscriptions with the security initializer, call `AddSecurityInitializer``add_security_initializer` before you create the subscriptions.

### Default Behavior [](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts/03%20Default%20Behavior.html)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#03-Default-Behavior)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)

The brokerage model of your algorithm automatically sets the fill model of each security. The default brokerage model is the `DefaultBrokerageModel`, which sets the [EquityFillModel](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/supported-models/equity-model) for Equities, the [FutureFillModel](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/supported-models/future-model) for Futures, the [FutureOptionFillModel](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/supported-models/future-option-model) for Future Options, and the [ImmediateFillModel](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/supported-models/immediate-model) for all other asset classes.

### Model Structure [](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts/04%20Model%20Structure.html)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#04-Model-Structure)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)

### Partial Fills [](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts/05%20Partial%20Fills.html)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#05-Partial-Fills)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)

In live trading, your orders can partially fill. For example, if you have a buy limit order at the bid price for 100 shares and someone sells 10 shares with a market order, your order is partially filled. In backtests, the pre-built fill models assume orders completely fill. To simulate partial fills in backtests, create a custom fill model.

### Stale Fills [](https://github.com/QuantConnect/Documentation/tree/master/03%20Writing%20Algorithms/24%20Reality%20Modeling/02%20Trade%20Fills/01%20Key%20Concepts/06%20Stale%20Fills.php)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts#06-Stale-Fills)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)[](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/trade-fills/key-concepts)

Stale fills occur when you fill an order with price data that is timestamped an hour or more into the past. Stale fills usually only occur if you trade illiquid assets or if your algorithm uses daily data but you trade intraday with Scheduled Events. If your order is filled with stale data, the fill price may not be realistic. The pre-built fill models can only fill market orders with stale data. To adjust the length of time that needs to pass before an order is considered stale, set the `StalePriceTimeSpan``stale_price_time_span` setting.

#### Example 2: Volume Share Fill

The following algorithm longs the top 10 liquid constituents and short the bottom 10 liquid constituents of QQQ. To realistically fill the less liquid stocks, we implement a fill model that only fills with at most 30% of the previous second bar.

 Select Language: C#Python

public class VolumeShareSlippageModelAlgorithm : QCAlgorithm{ private List<Symbol> _longs = new(); private List<Symbol> _shorts = new(); public override void Initialize() { SetStartDate(2024, 9, 1); SetEndDate(2024, 12, 31); // The security initializer applies the VolumeShareFillModel to all assets. UniverseSettings.Schedule.On(DateRules.WeekStart()); // Add universe to trade on the most and least liquid stocks among QQQ constituents. AddUniverse( // First, we select all QQQ constituents for the next filter on liquidity. Universe.ETF(qqq, Market.USA, UniverseSettings, (constituents) => constituents.Select(c => c.Symbol)), FundamentalSelection ); // Set a scheduled event to rebalance the portfolio at the start of every week.
