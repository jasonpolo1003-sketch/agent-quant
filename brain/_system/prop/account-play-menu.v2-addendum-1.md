# PROP-PLAY-v2 addendum 1 (2026-10-29, before any result)

Clarifies `account-play-menu.v2.json` (sha256 09470164..., commit 7a51f9e) for `scripts/menu_v2.py`. The menu and its hash are unchanged. Written after reading the menu, the code (firm_grid.py, state_sizing.py, prop/play.py, prop/firms.py) and the firm files, before any v2 cell was run.

1. **Unit of selection.** "Per firm file" is run as per (firm file, variant), as instructed by the orchestrator: 7 units. Topstep adapter (`--topstep`, topstep_50k.json + topstep_50k_xfa.json): standard/standard, standard/consistency, no_activation_fee/standard, no_activation_fee/consistency. `firms/topstep_50k_standard.json` (incl. $29/mo API): standard, consistency. `firms_indicative/lucid_flex_50k.json`: default. The stricter one-pick-per-file reading (the variant with the highest train lower bound inside a file) is also reported; its test cell is one of the per-variant test cells (same seed, same numbers), so it uses no extra test look.
2. **Grid.** 5 eval x 3 funded = 15 pairs per unit, 105 train cells; every train cell is a prop trial.
3. **Play.** Each pair is `Play(name, eval, funded, "consistency_safe", "funded_consistency_safe")` with the v1 defaults: no own daily loss stop, stop at target on, the firm's optional daily loss ON where offered (Topstep $1,000 soft; LucidFlex offers none in its file, so none). A named stop is dropped where the firm has no such rule (LucidFlex funded has no consistency share: no funded stop), exactly as `play.resolve` does.
4. **Caps.** Eval cap = the firm's max micros; funded cap = min(funded max micros, the scaling plan's start size if the file states one). Topstep: eval 50, XFA 20 (2-lot start). LucidFlex: eval 40, funded 20 (scaling $0-999 tier). No v2 size exceeds a cap, so no cut and no duplicate is expected; the script still cuts and de-duplicates (keeps the first pair in grid order) and records it.
5. **Selection.** On train years only, the pair with the highest lower 90% bound of mean net cash. Ties: the first in grid order (eval ascending, then funded ascending). LucidFlex gets a pick and a test cell (reported), but is never a final answer.
6. **Seeds and settings.** Train and test cells: horizon 42, 2,000 paths, outer 40, inner 300, L3, seed 20261027 (the repo default `replay.SEED`, as state_sizing.py). Luck: the random-direction control on the same resampled days with the same resolved play and sizes (`evaluate_play`).
7. **Test gate.** For each unit's pick only: mean net cash lower 90% bound > $0 AND (net - luck) lower 90% bound > $0. The test half is looked at once per unit (7 looks).
8. **Confirmation.** For each test pass (LucidFlex included, reported only): the same pick on the test years, outer 200 (paths 2,000, inner 300), fresh seed 20261029. It passes only if the same two lower bounds are > $0.
9. **Final answer.** Among Topstep units that pass the test gate AND the confirmation, the one with the highest confirmation lower bound of mean net cash; otherwise "none". Choosing among several passing units uses test data and is flagged as such.
10. **Reported on test for each pick:** chance of any payout, chance net > 0, 5th percentile of net cash, median trading days to the first payout, mean fees spent (strategy and luck).
11. **Ledger.** Every train, test and confirmation cell is one line in `prop_trials.jsonl`, kind "menu_v2", with a `split` field (train / test / confirm). Data: the workbench table of trial 266777ef (practice data 2019-05..2024-12); the script refuses if any table date is 2025 or later.
